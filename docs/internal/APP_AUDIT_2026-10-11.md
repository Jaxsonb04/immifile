## Fix before release: Assistant recovery loop

**P2, reproduced against production through the native app.** Ask “Help me with asylum,” then tap the offered **Renew my green card** suggestion. The second response repeats the unsupported-topic explanation instead of returning the I-90 recommendation. The quota falls from 20 to 19 to 18 even though the offered recovery does not recover.

`convex/navigator.ts:77–84` prioritizes an unsupported matter anywhere in the prior user history; line 143 returns that prior rejection. The frontend nevertheless offers supported recovery suggestions in `src/screens/assistant/assistant.recommendation.ts:112–116`. The existing backend test deliberately preserves prior-history screening, so a passing suite does not catch this product mismatch.

Add a clear new-topic/conversation boundary for these recovery actions, preserving safety checks for the active conversation. Verify unsupported-topic and legal-advice rejection → every supported suggestion, while retaining ambiguous follow-up context and rejecting forged instructions. This requires a backend change and deployment, followed by regression QA.

Evidence: `.gstack/qa-reports/2026-10-11/screenshots/pro-unsupported-recovery-loop.png`.

## Fix before release: quota disables official links

**P2, reproduced at the actual daily boundary on SE.** The app correctly enforces the 20-message daily limit, but it also disables every existing official-form link. The final accessibility snapshot contained **19 official USCIS form buttons, all disabled**, and the last successful I-765 recommendation displayed an unusable Open Form button. Opening a previously obtained government link should not spend or require a message.

`src/screens/assistant/assistant.data.ts:34–35` makes `canSend` false at zero remaining. `assistant.screen.tsx:219` passes `!canSend` into every message as `isBusy`; `assistant.message.tsx:87` forwards it to `assistant.recommendation-card.tsx:82`, which disables the link.

Separate message/suggestion/retry quota gating from permission to open an existing official URL. Verify I-90 and I-765 links at zero remaining and while another message is pending. This requires a client change, a new production build, and another TestFlight pass.

Evidence: `.gstack/qa-reports/2026-10-11/quota-final.log`, `screenshots/se-quota-exhausted.png`, and `screenshots/se-quota-dark.png` beneath the same evidence directory. The exhausted-quota footer is also cramped on the small phone; stacking its long reset message would improve readability.

## Additional concerns to verify, not confirmed native failures

- Assistant sending has no offline notice/cancel timeout, and the OpenAI fetch at `convex/lib/openaiChat.ts:69–76` has no explicit timeout. Test stalled requests, understandable errors, quota refunds, and retry without duplicate billing.
- Token transport errors become `null` in `src/components/immifile-convex-auth-provider.tsx:26–29`. An isolated test of the installed Convex authentication manager showed no token retry after two null results followed by websocket reconnect. The app's token fetcher remains stable for the same session ID. Confirm offline cold start → restore connectivity on the actual candidate before treating this as a proven app bug.
- The public case API accepts an optional `occurredAt` number without finite/range validation (`convex/cases.ts:212–224`). The shipping UI does not supply it. This is API hardening, not a reproduced native defect.
