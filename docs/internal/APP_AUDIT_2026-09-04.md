# App workflow and release audit — September 4, 2026

## Verdict

The four shipping surfaces are substantially improved and the exercised development
workflows pass. **This is not final App Store sign-off.** Physical-device provider
flows, actual offline behavior, and the final production TestFlight binary still
need verification. Production was inspected read-only; these code changes have not
been deployed to production or submitted to Apple.

Branch: `codex/release-workflow-audit`, starting from `71daaa2`.

## Scope and method

Reviewed the route inventory, release policy, account/session transitions, case
operations, assistant consent/history/recommendations, resource links, legal/support
screens, backend ownership and feature gates, build configuration, and existing tests.
Exercised native UI with Maestro and serve-sim accessibility trees/screenshots.

- iPhone SE (3rd generation), iOS 18.1, 375 × 667 points.
- iPhone 17 Pro, iOS 26.5, 402 × 874 points.
- Standard text on both; accessibility-extra-extra-large text on SE.
- Light appearance and selected dark-appearance screens on Pro.
- Rebuilt the development client after discovering the installed binaries lacked
  the current ExpoCrypto native module. Build completed with 0 errors and 11 warnings.
- Used only disposable development accounts and synthetic receipt numbers.
- Synced the confirmed **development** Convex deployment: its old preference query
  still threw during account conversion although the checked-out source handled
  an unresolved session. Retesting used the synchronized backend.

The disabled filing/community implementations were covered by source review and
backend tests, not presented as completed native user journeys. This audit does not
claim every possible device, input, timing condition, or external service was tested.

## Missing features and release decisions

These are visible scope gaps, rather than inert buttons accidentally left in the UI:

- **Password recovery is disabled.** Users receive a warning during signup, but a
  forgotten password still prevents normal self-service access. Enabling it requires
  verified email delivery and a deliberate release-policy change. Treat this as a
  material product limitation when deciding whether to release email signup.
- Case tracking is manual: no automatic refresh from USCIS, push notifications,
  reminders, or deadline tracking. The UI explicitly describes manual updates.
- The case editor cannot correct/delete individual timeline entries, choose their
  historical dates, or edit an existing receipt number. Removing/re-adding a case
  loses its entered timeline. The status menu also does not represent denied or
  withdrawn outcomes. These are useful follow-up case-management features.
- Filing preparation, interviews, document upload and community are intentionally
  disabled and must not be advertised in the release listing.
- Personal details routes are part of the disabled filing surface; general account
  profile editing is not available from the shipped Account tab.
